Guia de Início Rápido (Quickstart)

SoftForge — Framework Fullstack AI-Native
100% construído com e para IA • Spec-Driven • Vertical Slice Architecture • Docker-First

1. Pré-requisitos

  • Python 3.12+ (com pip ou uv)
  • Node.js 20+ (com npm ou pnpm)
  • Docker e Docker Compose (opcional para SQLite, obrigatório para Postgres em produção)

2. Inicialização em 3 Passos

Passo 1: Configurar Variáveis

cp .env.example .env

Passo 2: Iniciar o Backend

# Criar ambiente virtual
python -m venv apps/api/.venv

# Ativar e instalar (Windows):
.\apps\api\.venv\Scripts\python.exe -m pip install -e "apps/api[dev]"

# Executar API com recarga automática:
.\apps\api\.venv\Scripts\python.exe -m uvicorn src.main:app --reload

Passo 3: Criar uma Nova Fatia em 2 Minutos

python tools/scripts/slice_scaffold.py --name invoices

Esse comando gera schemas Pydantic v2, models SQLAlchemy 2.0 Async, service, router e testes com SQLite in-memory.

Manual do Framework

1. Por que Vertical Slice Architecture?

Em arquiteturas em camadas convencionais (controllers, services, repositories separados), o código de uma funcionalidade fica espalhado em várias pastas. Quando uma IA atua no projeto, ela precisa manter muitos arquivos na janela de contexto de tokens, gerando alucinações.

No SoftForge, cada fatia é 100% autossuficiente:

apps/api/src/slices/<feature>/
├── schemas.py       # Contratos OpenAPI & DTOs Pydantic v2
├── models.py        # Tabelas SQLAlchemy 2.0 Async
├── service.py       # Lógica pura de negócio
├── router.py        # Endpoints HTTP da fatia
└── tests/           # Testes de integração isolados com SQLite

2. Multi-Tenancy e RBAC

Hierarquia de papéis por Workspace:

  • Owner (Nível 4): Controle total da organização e faturamento.
  • Admin (Nível 3): Gestão de membros e configurações de projetos.
  • Member (Nível 2): Criação e edição de dados do domínio.
  • Viewer (Nível 1): Apenas visualização.

Fluxo de Desenvolvimento com IA

A Constituição do Agente (.ai/AGENTS.md):

O arquivo .ai/AGENTS.md na raiz do projeto instrui qualquer IA (Cursor, Antigravity, Claude Code) a nunca quebrar as regras de fatias verticais, nunca misturar modelos de banco com DTOs e sempre rodar o validador de guardrails.

O Ciclo Determinístico em 7 Etapas:

  1. Scaffold: python tools/scripts/slice_scaffold.py --name <fatia>
  2. Contratos: Definir entrada e saída em schemas.py
  3. Lógica: Implementar service.py e rotas em router.py
  4. Testes: Cobrir com testes assíncronos em tests/
  5. Exportar: python tools/scripts/export_openapi.py
  6. Documentar: Atualizar guias em docs/ e regras em .ai/
  7. Verificar: python tools/scripts/verify.py

Regra de Ouro: Documentação para IA

"Se não está documentado no ecossistema, para a IA não existe."

Agentes de IA constroem e operam sistemas lendo documentação em tempo real. Se você alterar ou adicionar código sem documentar na mesma entrega, os próximos agentes sofrerão alucinações e quebrarão convenções. Toda evolução do código acompanha a evolução da documentação.

Fatia: Autenticação Social & OAuth2

A fatia auth oferece suporte nativo a login com um clique via Google e GitHub, além do fluxo tradicional de e-mail e senha:

  • Auto-Linking Inteligente: Vincula contas sociais automaticamente a usuários cadastrados previamente com o mesmo e-mail verificado.
  • Tabela Dedicada: oauth_accounts armazena pares (provider, provider_user_id) únicos por usuário.
  • Senhas Opcionais: Usuários de login social possuem hashed_password nulo com suporte a definição de senha posterior.
  • Desenvolvimento Offline: Mock automático ativado quando nenhuma chave for configurada, permitindo login instantâneo com códigos de teste.
GET /api/v1/auth/oauth/{provider}/authorize  -> Gera URL de consentimento
GET /api/v1/auth/oauth/{provider}/callback   -> Valida code, autentica e emite tokens

Fila Assíncrona & Background Workers (Arq + Redis)

Motor de processamento assíncrono em segundo plano e cron jobs periódicos desacoplados da API:

  • 100% Asyncio Nativo: Utiliza o Arq sobre Redis 7, operando com funções async def e compatível diretamente com SQLAlchemy 2.0 Async e httpx.
  • Isolamento em Contêiner: O serviço worker roda em contêiner dedicado no docker-compose.yml.
  • Desenvolvimento & Testes Offline: FakeQueueClient em memória permite enfileirar e testar tarefas no pytest em menos de 1 segundo sem necessidade de Redis ativo.
  • Cron Integrado: Agendamento declarativo de expurgo de tokens revogados às 03:00 UTC diariamente.
queue = await get_queue()
job_id = await queue.enqueue("send_transactional_email", to_email="...", subject="...")

Fatia: Auditoria & Compliance

Trilha imutável de auditoria com despacho desacoplado em segundo plano e rastreabilidade pericial:

  • Latência Zero no Request: Disparo assíncrono via Arq Worker com enfileiramento instantâneo no Redis (< 15ms).
  • Imutabilidade Estrita: Tabela append-only sem coluna updated_at para conformidade com LGPD/GDPR e SOC2.
  • Rastreabilidade de Rede: Captura de IP real (com headers de proxy reverso) e User-Agent em cada evento.
  • Preservação de Histórico: E-mail do autor persistido diretamente no registro caso o usuário seja expurgado.
  • Controle RBAC: Endpoint de consulta restrito a usuários com perfil mínimo de Administrador.
GET /api/v1/workspaces/{workspace_id}/audit-logs -> Lista paginada de eventos

Fatia: Notificações In-App & WebSockets

Centro de notificações em tempo real com entrega instantânea e sincronização de leituras:

  • Canal WebSocket Full-Duplex: Endpoint autenticado via token JWT (/api/v1/notifications/ws?token=...) para entrega imediata sem necessidade de polling contínuo.
  • Gerenciador Multitela: Suporta múltiplos dispositivos e abas abertas simultaneamente pelo mesmo usuário.
  • Badge Dinâmico: Endpoint leve /unread-count para alimentar o contador sobre o ícone de sino na barra de navegação.
  • Histórico Persistido: Armazenamento na tabela notifications com categorias (billing, project, team, system).
  • Operações em Massa: Marcação de leitura individual (PATCH /{id}/read) e em lote (POST /mark-all-read).
GET   /api/v1/notifications              -> Lista paginada de notificações
GET   /api/v1/notifications/unread-count -> Total de não lidas para o badge
PATCH /api/v1/notifications/{id}/read    -> Marca notificação individual como lida

Fatia: Webhooks Outbound

Motor de integração outbound desacoplado via Arq Worker com assinatura criptográfica:

  • Despacho Desacoplado: As requisições HTTP são processadas em segundo plano pelo Arq Worker com latência zero para o cliente da API.
  • Assinatura HMAC-SHA256: Cabeçalho X-SoftForge-Signature: t={timestamp},v1={hex_digest} protegendo contra adulteração e ataques de repetição.
  • Inscrição Granular: Suporte a tópicos específicos (ex: ["project.created"]) ou curinga ["*"].
  • Rastreabilidade de Entregas: A tabela webhook_deliveries registra o código HTTP retornado, corpo de resposta e eventuais erros.
  • Testes Offline: URLs com prefixo mock:// são resolvidas instantaneamente pelo worker em testes automatizados.
POST   /api/v1/workspaces/{id}/webhooks                  -> Cadastra endpoint
GET    /api/v1/workspaces/{id}/webhooks                  -> Lista endpoints
GET    /api/v1/workspaces/{id}/webhooks/{id}/deliveries  -> Histórico de entregas

Fatia: Chaves de API & PAT (Machine-to-Machine)

Autenticação programática de alta segurança para Agentes Autônomos de IA, ferramentas CLI e pipelines CI/CD:

  • Autenticação M2M Nativa: Permite que agentes externos de IA (ex: Cursor, Claude Dev, AutoPR) consumam a API via cabeçalho X-API-Key: sf_live_... ou Authorization: Bearer sf_live_....
  • Criptografia com Hash SHA-256: O segredo em texto puro é exibido exclusivamente no momento da criação. O banco de dados armazena apenas o digest SHA-256 (hashed_key).
  • Prefixo Mascarado para Auditoria: A listagem exibe o prefixo e sufixo mascarados (ex: sf_live_abc1...9xyz) para identificação visual sem vazamento de segredos.
  • Validade Temporal & Expiração: Suporte a prazo de expiração em dias (expires_in_days) ou validade permanente.
  • Revogação Instantânea: Invalidada no banco no momento do clique, gerando 401 Unauthorized imediato para requisições subsequentes.
  • Isolamento Multi-Tenant Rigoroso: Toda chave é vinculada ao seu workspace. Tentativas de acessar recursos de outros workspaces são bloqueadas pelo RBAC com 403 Forbidden.
POST   /api/v1/workspaces/{id}/api-keys       -> Cria chave e retorna segredo bruto
GET    /api/v1/workspaces/{id}/api-keys       -> Lista chaves registradas (mascaradas)
DELETE /api/v1/workspaces/{id}/api-keys/{id}  -> Revoga chave de API imediatamente

Fatia: Convites de Equipe & Gestão de Membros (RBAC)

Colaboração multi-usuário com convites por e-mail, tokens criptográficos e controle hierárquico de acessos:

  • Convites Seguros por Token: Token de 32 bytes de alta entropia com expiração em 7 dias (expires_at).
  • Disparo de E-mail Assíncrono: Enfileirado no Redis e processado em segundo plano pelo Arq Worker com latência zero para a API.
  • Adesão Instantânea: Aceitação do convite via endpoint POST /invites/accept integrando o usuário imediatamente ao workspace.
  • Hierarquia RBAC Rigorosa: Owner (4), Admin (3), Member (2) e Viewer (1).
  • Proteção Contra Remoção do Owner: O proprietário nunca pode ser expulso nem rebaixado, e a transferência de posse exige autorização do proprietário atual.
  • Prevenção de Duplicidades: Bloqueia envio de convites para colaboradores que já são membros ativos do workspace.
POST   /api/v1/workspaces/{id}/invites          -> Envia convite de equipe por e-mail
GET    /api/v1/workspaces/{id}/invites          -> Lista convites pendentes
DELETE /api/v1/workspaces/{id}/invites/{id}     -> Revoga convite pendente
POST   /api/v1/workspaces/invites/accept        -> Aceita convite via token
GET    /api/v1/workspaces/{id}/members          -> Lista membros ativos da equipe
PATCH  /api/v1/workspaces/{id}/members/{user_id}-> Altera cargo RBAC de membro
DELETE /api/v1/workspaces/{id}/members/{user_id}-> Remove membro do workspace

Fatia: Storage & Gerenciamento de Arquivos

Armazenamento unificado de anexos, documentos e imagens de perfil com suporte híbrido para nuvem e offline:

  • Provedor Híbrido: Opera localmente na pasta uploads/ durante desenvolvimento e testes offline, e compatível com AWS S3, Cloudflare R2 e MinIO em produção.
  • Isolamento Multi-Tenant: Arquivos privados vinculados a workspaces são bloqueados contra acesso de usuários de tenants externos com 403 Forbidden.
  • Arquivos Públicos: Avatares de usuário (/users/me/avatar) são servidos de forma pública sem cabeçalho de autenticação para renderização instantânea no navegador.
  • Limites de Upload: Controle rígido de tamanho máximo (MAX_UPLOAD_SIZE_MB) com retorno 413 Payload Too Large para arquivos excessivos.
  • Sanitização de Nomes: Limpeza regex de nomes de arquivos para prevenir ataques de *path traversal* (../).
POST   /api/v1/workspaces/{id}/storage/upload       -> Upload de arquivo multipart
GET    /api/v1/workspaces/{id}/storage/files        -> Lista arquivos do workspace
DELETE /api/v1/workspaces/{id}/storage/files/{id}   -> Exclui arquivo físico e registro
GET    /api/v1/storage/files/{id}/download          -> Download ou streaming binário
POST   /api/v1/users/me/avatar                      -> Upload de foto de perfil pública

Fatia: Rate Limiting & Proteção Contra Abuso

Motor de proteção de tráfego com janelas deslizantes (Sliding Window Log) e fallback resiliente:

  • Janela Deslizante de Alta Precisão: Em produção, utiliza Redis Sorted Sets (ZSET) com timestamps em microssegundos para contagem sem anomalias de fronteira.
  • Fallback Graceful para Memória: Em ambientes offline de desenvolvimento e testes unitários, chaveia automaticamente para MemoryRateLimiter com collections.deque.
  • Cabeçalhos RFC 6585 / IETF: Emite X-RateLimit-Limit, X-RateLimit-Remaining e X-RateLimit-Reset em todas as respostas controladas.
  • Proteção HTTP 429: Retorna 429 Too Many Requests com o cabeçalho Retry-After especificando os segundos exatos para desbloqueio.
  • Chaves Multi-Critério: Suporte a limitação por IP do cliente (para rotas públicas como /login e /register), por ID de usuário ou por Workspace Tenant.
  • Diagnóstico de Sistema: Endpoint GET /api/v1/system/rate-limit para verificação do status do motor e backend ativo.
GET    /api/v1/system/rate-limit                    -> Status e backend do rate limiter
POST   /api/v1/auth/login     (com Rate Limiting)   -> 60 req/min por IP com headers RFC
POST   /api/v1/auth/register  (com Rate Limiting)   -> 60 req/min por IP com headers RFC

Fatia: Feature Flags & Toggles de Tenant

Lançamento progressivo de recursos, ativação dinâmica de funcionalidades beta e customização granular por Workspace:

  • Catálogo Global de Flags: Tabela feature_flags para registro de identificadores chave (slugs como beta_copilot) com status booleano global padrão.
  • Substituições por Workspace (Overrides): Tabela feature_flag_overrides permitindo que um tenant específico tenha flags ativadas ou desativadas independentemente do padrão global.
  • Avaliação em Requisição Única: Endpoint GET /api/v1/workspaces/{id}/features retorna o mapa consolidado completo para consumo no frontend.
  • Guarda Declarativa de Rotas: Injeção da dependência require_feature_flag(key) que bloqueia chamadas não autorizadas com HTTP 403 Forbidden e código FEATURE_FLAG_DISABLED.
  • Trilha de Auditoria: Criação, edição, exclusão e substituições registradas de forma assíncrona no histórico de auditoria.
GET    /api/v1/system/features                      -> Lista catálogo global de flags
POST   /api/v1/system/features                      -> Cadastra nova flag de sistema
PATCH  /api/v1/system/features/{id}                 -> Altera status global da flag
DELETE /api/v1/system/features/{id}                 -> Exclui flag e overrides associados
GET    /api/v1/workspaces/{id}/features             -> Retorna mapa avaliado para o workspace
POST   /api/v1/workspaces/{id}/features/{id}/override -> Força ativação/desativação no tenant
DELETE /api/v1/workspaces/{id}/features/{id}/override -> Remove substituição local do tenant
GET    /api/v1/workspaces/{id}/features/demo-guarded -> Endpoint modelo protegido por flag

FAQ & Solução de Problemas

Por que o arquivo docs/dist/index.html abre quebrado/feio ao dar dois cliques?

O VitePress compila o CSS e os scripts JS com caminhos absolutos como /assets/style.css. No protocolo local file:///, o navegador busca na raiz do disco rígido (onde não existem) e bloqueia módulos ES por políticas de segurança CORS.

Como resolver:

  • VitePress com busca e temas: Dê duplo clique em docs.bat (ou rode .\docs.ps1). Ele abre o site completo em http://localhost:5174.
  • Sem servidor (zero dependências): Abra este arquivo diretamente (docs/manual-offline.html). Ele funciona 100% nativo em file:///!
